# 前端性能优化清单（可执行）

> 目标：聚焦 Core Web Vitals（LCP/INP/CLS）与关键时延（TTFB/FCP/TTI/Long Task），建立“度量→优化→监控→守门”的闭环。

## 1) 目标指标与阈值
- LCP：良好 ≤ 2.5s，需改进 2.5–4s，较差 > 4s
- INP：良好 ≤ 200ms，需改进 200–500ms，较差 > 500ms
- CLS：良好 ≤ 0.1，需改进 0.1–0.25，较差 > 0.25
- 其他：TTFB、FCP、TTI、Long Task（>50ms）

## 2) 诊断工具（先度量）
- Lighthouse（本地/CI）：性能分、机会与诊断
- Chrome DevTools：Performance/Network/Coverage/Memory/Recorder
- WebPageTest/PageSpeed Insights：外网、地区/设备仿真
- RUM（真实用户监控）：web-vitals SDK 上报 LCP/INP/CLS

## 3) 关键渲染路径（CRP）
- [ ] 首屏关键 CSS 内联；非关键 CSS 延后（media/route-split）
- [ ] 业务脚本默认 `defer`；第三方/独立依赖用 `async`
- [ ] 预连接/预加载：`preconnect`、`dns-prefetch`、`preload`
- [ ] 启用 HTTP/2 或 HTTP/3；域名收敛；CDN 边缘缓存

示例（HTML 片段）：
```html
<link rel="preconnect" href="https://cdn.example.com" crossorigin>
<link rel="preload" as="style" href="/critical.css">
<script defer src="/app.js"></script>
```

## 4) 图片与多媒体
- [ ] 使用 WebP/AVIF；按质量与分辨率压缩，去 EXIF
- [ ] 响应式图片：`srcset/sizes`；图标优先 SVG/Iconfont
- [ ] 懒加载：`loading="lazy"`、IntersectionObserver；骨架占位防 CLS
- [ ] `decoding="async"`；视频封面/自动播放策略优化

```html
<img src="hero.webp" srcset="hero@1x.webp 1x, hero@2x.webp 2x" loading="lazy" decoding="async">
```

## 5) 字体
- [ ] `font-display: swap`，避免 FOIT；字体子集化与合并
- [ ] 只保留必要字重；关键字体可 `preload`
```css
@font-face { font-display: swap; }
```

## 6) JavaScript 体积与执行
- [ ] 路由/组件/功能级分包；`import()` 动态加载
- [ ] Tree-shaking/移除 dead code；仅引入 ESM 变体
- [ ] 长任务切片（>50ms）；重计算放 Web Worker
- [ ] Polyfill 仅按需；第三方脚本延迟/条件加载

```js
// Worker 示例
const worker = new Worker(new URL('./calc.worker.js', import.meta.url));
worker.postMessage({ payload });
```

## 7) 渲染与交互（INP/CLS）
- [ ] 动画仅使用 `transform/opacity`；避免强制同步布局
- [ ] 虚拟列表/分页加载；避免一次性渲染大 DOM
- [ ] 事件：`passive: true` 滚动；节流/防抖；合理事件委托
```js
window.addEventListener('scroll', onScroll, { passive: true });
```

## 8) 缓存与离线
- [ ] 静态资源强缓存 + 文件名指纹；HTML 不缓存/短缓存
- [ ] Service Worker：图片 CacheFirst、API SWR/NetworkFirst、预缓存关键壳
```js
// Workbox（伪）：
registerRoute(imgMatch, new CacheFirst({ cacheName: 'images' }));
registerRoute(apiMatch, new StaleWhileRevalidate({ cacheName: 'api' }));
```

## 9) SSR/SSG/ISR 与边缘渲染
- [ ] 首屏 SSR/SSG/ISR（可流式）；CDN 边缘函数降低首包
- [ ] 选择性/延迟水合；组件级懒水合

## 10) 第三方资源治理
- [ ] 审计：是否必要？能否自托管？是否可延迟/按路由按需？
- [ ] 控制：统一加载入口、错误隔离、降级策略、A/B 条件加载

## 11) 构建与发布
- [ ] 使用 Vite/Rspack/esbuild；依赖预构建
- [ ] 产物分析：Bundle Analyzer/`rollup-plugin-visualizer`
- [ ] 现代/旧版差异化产物（module/nomodule）；SourceMap 策略

## 12) 监控与守门（持续化）
- [ ] Performance Budget：体积/请求数/LCP/INP/CLS 阈值
- [ ] CI 接入 Lighthouse CI；产物体积报告（bundlesize）
- [ ] 线上 RUM：web-vitals 上报 + 告警阈值

# 可执行脚本与集成建议

## A. 基线度量（本地）
- 使用 pnpm：
```bash
pnpm dlx lighthouse https://example.com --view --chrome-flags="--headless" \
  --only-categories=performance --preset=desktop
```

## B. CI 守门
- Lighthouse CI（示例 .lighthouserc.json）：
```json
{
  "ci": {
    "collect": { "url": ["http://localhost:4173"], "numberOfRuns": 3 },
    "assert": {
      "assertions": {
        "categories:performance": ["error", { "minScore": 0.9 }],
        "unminified-javascript": "warn"
      }
    }
  }
}
```

## C. 产物分析
- Vite 可用 `rollup-plugin-visualizer`：
```bash
pnpm add -D rollup-plugin-visualizer
```
- 在 `vite.config.ts`：
```ts
import { visualizer } from 'rollup-plugin-visualizer';
export default { build: { rollupOptions: { plugins: [visualizer()] } } };
```

## D. 线上 RUM（web-vitals）
```js
import { onCLS, onINP, onLCP } from 'web-vitals';
function send(metric) { navigator.sendBeacon('/rum', JSON.stringify(metric)); }
onCLS(send); onINP(send); onLCP(send);
```

# DevTools 快速排查步骤
- Network：按时间线查看阻塞资源、TTFB、缓存命中、协议
- Performance：标记 LCP/INP、查找 Long Task、查看渲染/脚本栈
- Coverage：发现未使用的 CSS/JS
- Memory：快照/泄漏排查；性能面板配合看 JS 堆增长

# 优先级实施路线（建议）
1. 快速收益（1–2 天）：图片/字体/阻塞资源/第三方脚本整治
2. 体积与执行（2–4 天）：分包、Tree-shaking、长任务切片、Worker
3. 架构与缓存（3–7 天）：SSR/边缘渲染、SW 策略、HTTP 缓存体系
4. 守门与监控（1 天）：CI 阈值、RUM 上报与告警

---

结语：先度量，后优化；以 CWV 为锚，建立自动化与守门，持续迭代。
