# 提示词工程速记卡（如何更高效和大模型沟通）

## 核心原则
- 明确目标与约束：告诉模型你要什么、不要什么、成功标准是什么。
- 结构化输入/输出：给定固定字段和格式，减少歧义。
- 示例驱动（Few-shot）：用 1–3 个高质量示例对齐风格与边界。
- 逐步分解：把复杂任务拆成子任务或分阶段生成。
- 迭代与评测：用“期望—对比—修正”闭环快速收敛。

## 高效沟通流程（B-G-O-F-E-S）
- 背景（Background）：域、受众、使用场景。
- 目标（Goal）：产出类型、完成定义（DoD）。
- 约束（Constraints）：字数、语气、风格、合规、禁区。
- 输出格式（Output）：结构化模板/JSON Schema/Markdown 表。
- 评估标准（Evaluation）：正确性、覆盖率、可运行性、示例对齐。
- 示例（Samples）：1–3 个正样例；必要时给反例。

示例骨架
```
[背景] 你是{角色}，读者是{对象}，场景是{场景}。
[目标] 产出{类型}，满足{成功标准}。
[约束] 风格{风格}，长度{字数}，禁止{禁区}，遵循{规范}。
[输出格式] 严格按如下结构输出：
- 标题：
- 要点（3-5条）：
- 风险与边界：
- 结论：
[评估标准] 正确性≥{阈值}；包含{必含要素}；如不确定，先提问澄清。
[示例]
- 正例：...
- 反例：...
先思考步骤，但仅输出最后结果与理由（不要暴露思考细节）。
```

## 常用技巧
- 角色扮演（Role prompting）：指定“你是…专家/审稿人/QA”改变输出视角。
- Few-shot 对齐：提供最小“好答案”示例，模型会模仿风格和结构。
- 任务拆解：
  - 先列提纲→再扩写。
  - 先生成代码→再生成测试→再生成文档。
- 结构化输出：
  - JSON Schema（要求验证通过）
  - Markdown 固定段落（避免自由发挥）
- 拒答与澄清：
  - 不足信息时先提 3 个澄清问题；不确定性请标注。
- 负面提示（Anti-prompt）：
  - 禁止：编造数据/超出范围/泄露密钥/输出思维链。
- 自检/评审：
  - 让模型自审对照清单，再输出修订版。

## 输出模板库（可直接复用）

- 通用问答
```
任务：{问题或目标}
必须包含：{关键点}
输出格式：
- 结论（1-2句）：
- 关键依据（3-5条）：
- 风险与边界：
- 推荐行动（步骤化）：
```

- 代码生成/修复
```
目标：实现/修复 {功能}
上下文：{相关文件/片段}
约束：语言{X}，版本{Y}，必须可运行；不输出多余注释
输出：
- 变更点列表（文件/位置/原因）
- 代码块（逐文件）
- 快速验证步骤（命令/用例）
若信息不足，先提 3 个澄清问题再继续。
```

- 架构/设计评审
```
对象：{方案/代码/流程}
评审维度：正确性/复杂度/性能/安全/可维护/可观测
输出：
- 优点（3-5）
- 主要问题（按严重级/证据）
- 修复建议（分短期/长期）
- 风险清单与缓解
```

- 数据抽取/归纳（结构化）
```
输入：{文本}
任务：抽取 {字段A,B,C}
输出（JSON 数组），每项：
{ "A": "...", "B": "...", "C": "..." }
要求：字段完整，若缺失用 null，不得新增字段。
```

- 检索/引用（RAG）
```
上下文（引文块，带编号）：[1]… [2]…
任务：回答问题并标注引用来源编号
输出：
- 回答：
- 引用：[1],[3]（必须只选自上文）
如信息不足，回答“无法从提供上下文确定”，并指出缺口。
```

## 质量控制技巧
- 明确“完成定义”：可运行/测试通过/校验 OK（例如“返回 JSON 必须能被 JSON.parse 解析”）。
- 引入“对照清单”：
  - 是否覆盖所有必需点？
  - 是否遵循格式与长度？
  - 是否给出风险与边界？
- 约束输出长度与风格：如“每条不超过 20 字”“不使用学术化词汇”。

## 反模式（避免）
- 指令过短：只给一个标题，输出随机。
- 目标与格式未定义：自由发挥导致不可用。
- 长上下文无重点：不做“任务/约束/格式”提炼。
- 要求“展示思维链”：可能导致冗长且不稳定。正确做法是“先思考但仅输出结论与关键理由”。

## 迭代优化闭环（三步）
- 第 1 次：拿到初稿，看是否满足目标/格式/边界。
- 第 2 次：指出“差距清单”（缺失点/错误点/风格不符），要求仅修补差距。
- 第 3 次：让模型自检对照清单，打分并再次微调。

## 不同任务的最小提示模版
- 生成简历要点：限定“量化指标/影响/方法/角色，分别 3–5 条，动词开头，≤15 字/条”。
- 面试速记：限定“问题库（10 问）+ 标准答案要点（3 条/问）+ 追问（1 条/问）”。
- 文档摘要：限定“核心结论（3 条）+ 证据（3 条，标页码/段落）+ 不确定点（2 条）”。

## 快速选择指南
- 需要一致格式 → 强制模板/JSON Schema。
- 需要精准事实 → 提供上下文片段并要求标注引用编号。
- 需要创作风格对齐 → 给“黄金示例”而非抽象要求。
- 需要可靠代码 → 明确运行环境/版本/测试用例与通过标准。

## 一个小示例（把任务说清楚）
不佳：
- “帮我写前端性能优化建议”

更好：
```
你是资深前端性能顾问。目标：为 React 中台应用提出性能优化建议。
约束：不改变业务功能；建议可在两周内落地；每条含“收益估计与风险”。
输出格式：
- 优先级（P1/P2）- 建议标题
- 做法（≤3步）
- 预期收益（量化/估计）
- 风险与回滚
先给出 P1 的 3 条，再给 P2 的 3 条。
```
